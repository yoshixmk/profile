# 開発サーバー起動と記事確認スキル

このスキルは、Next.js開発サーバーを起動し、ブログ記事が正しく表示されるか確認するためのものです。

## 使用方法

ユーザーが「記事を確認して」「開発サーバーを起動して」などと言った場合、このスキルを使用します。

## 実行手順

### 1. 開発サーバーの状態確認

まず、既に開発サーバーが起動しているか確認します：

```
listProcesses ツールを使用して、実行中のプロセスを確認
```

### 2. 開発サーバーの起動（起動していない場合）

開発サーバーが起動していない場合、以下のコマンドで起動します：

```
controlPwshProcess ツールで action="start", command="pnpm run dev" を実行
```

### 3. サーバーの準備待機

サーバーが完全に起動するまで待機します（通常5-10秒）：

```
timeout /t 8 /nobreak コマンドで待機
getProcessOutput ツールでサーバーログを確認し、"Ready" メッセージを確認
```

### 4. ビルド済みファイルの確認

静的ビルドが最新かどうか確認します：

```
listDirectory ツールで out/ ディレクトリの内容を確認
必要に応じて pnpm run build を実行
```

### 5. 記事ファイルの確認

特定の記事が正しく生成されているか確認します：

```
# 日本語ブログ記事の一覧
listDirectory で out/ja/blog/ を確認

# 英語ブログ記事の一覧
listDirectory で out/en/blog/ を確認

# 特定の記事のHTMLを確認（必要に応じて）
Select-String コマンドでHTMLファイル内のキーワードを検索
```

### 6. アクセス情報の提供

ユーザーに以下の情報を提供します：

- ローカルURL: `http://localhost:3000`
- 日本語トップページ: `http://localhost:3000/ja`
- 英語トップページ: `http://localhost:3000/en`
- 日本語ブログ: `http://localhost:3000/ja/blog`
- 英語ブログ: `http://localhost:3000/en/blog`

## 注意事項

- 開発サーバーは長時間実行プロセスなので、`controlPwshProcess` の `start` アクションを使用すること
- `executePwsh` で `pnpm run dev` を実行しないこと（ブロックされる）
- サーバーログに "Ready" が表示されるまで待機すること
- 既に起動している場合は、再起動せずにそのまま使用すること

## トラブルシューティング

### サーバーが起動しない場合

1. ポート3000が既に使用されていないか確認
2. `pnpm install` で依存関係を再インストール
3. `.next` ディレクトリを削除して再ビルド

### 記事が表示されない場合

1. ビルドを再実行: `pnpm run build`
2. MDXファイルの構文エラーを確認
3. frontmatterが正しく設定されているか確認

## 例

ユーザー: 「記事を確認して」

応答:
1. 開発サーバーの状態を確認
2. 起動していなければ起動
3. サーバーログで "Ready" を確認
4. ビルド済みファイルを確認
5. 「開発サーバーが起動しました。http://localhost:3000 でアクセスできます」と報告
