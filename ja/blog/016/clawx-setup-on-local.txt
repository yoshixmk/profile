## はじめに

ローカル環境でLLMを動かしてClawXと連携する、という構成に興味を持っている方は多いと思います。クラウドAPIに頼らずに済む点や、プライバシー面での安心感が主な魅力です。

今回は **Qwen3.5 9B** を LM Studio 経由で起動し、ClawX（旧 Open Claw）から操作できるようにするまでの設定手順と、実際に試してみてわかったいくつかのポイントをまとめます。設定をひとつ間違えるだけでエラーが出たり、LLMが応答を返さなくなったりするので、この記事がそのトラブルを未然に防ぐ手助けになれば幸いです。

---

## 検証環境（マシン性能）

まず前提として、今回の検証に使ったマシンのスペックを共有しておきます。

| 項目 | 詳細 |
|------|------|
| CPU | AMD Ryzen 7 8845HS w/ Radeon 780M Graphics |
| コア / スレッド | 8コア / 16スレッド |
| 最大クロック | 3,801 MHz（3.8 GHz） |
| GPU | AMD Radeon 780M（統合グラフィックス） |
| メモリ | 約 32 GB（31,941 MB） |
| OS | Windows 11（Build 26200）64bit |

Ryzen 7 8845HS はモバイル向けの高性能 APU で、AI 処理向けの NPU も内蔵しているモデルです。9B クラスのモデルをローカルで動かすには十分なスペックと言えますが、あくまでラップトップの統合 GPU であるため、デスクトップの専用 GPU と比べると推論速度には差があります。「強くはないが、動く」という立ち位置です。

---

## 設定ポイント一覧

LM Studio 側で調整が必要な項目は主に以下の 4 つです。それぞれ詳しく説明します。

1. コンテキストサイズ
2. システムプロンプト
3. Thinking（Enable Thinking）
4. Temperature

---

## 1. コンテキストサイズ

**設定場所**: LM Studio → モデル設定 → Context and Offload → Context Length

### なぜデフォルト値では足りないのか

LM Studio のデフォルトのコンテキストサイズは **8,192 トークン** です。一見十分に見えますが、ClawX はツール呼び出しの結果やシステムプロンプト、会話履歴をすべてコンテキストに積み上げていくため、少し複雑な作業をさせるとすぐに上限に達してしまいます。その結果、ClawX 側でエラーが発生します。

### 推奨値

最低でも **30,000 トークン以上** を設定することを強く推奨します。筆者は以下の値を使っています。

- `88,888`
- `99,999`

「なぜこの数字？」と思われるかもしれませんが、単純に **覚えやすい** からです。100,000 を超えても動作に問題はありませんが、キリの良い数字より少し低めにしておくことで誤入力を防げます。

> **注意**: コンテキストサイズを増やすとメモリ消費も増加します。32 GB 環境であれば 99,999 程度は問題なく動作しましたが、メモリが少ないマシンでは値を調整してください。

---

## 2. システムプロンプト

**設定場所**: LM Studio → モデル設定 → System Prompt

ClawX を使うにあたって、モデルに対して「ClawX の機能を積極的に使うこと」「OS が Windows であること」を明示的に伝えることが重要です。

```txt
You should use ClawX feature actively. The OS is Windows.
```

これだけでも多くの場合は十分ですが、モデルが指示通りに動いてくれない場合は、**具体的な目的や制約を追記**すると効果的です。

### カスタマイズ例

意図しないファイル削除やシステム変更を防ぎたい場合は、以下のような制約を加えるとよいでしょう。

```txt
You should use ClawX feature actively. The OS is Windows.
Do not perform any destructive operations such as deleting files or modifying system settings without explicit confirmation.
```

ローカル LLM はクラウド API と比べて指示追従性が低い場合があるため、システムプロンプトで明確にルールを定めておくと安定性が上がります。

---

## 3. Thinking（Enable Thinking）

**設定場所**: LM Studio → モデル設定 → Custom Fields → Enable Thinking

### 結論: **OFF にする**

`Enable Thinking` を ON にすると、モデルが内部的な思考プロセスをトークンとして生成してから回答します。精度向上を期待してこの機能を有効にしたくなりますが、ローカル LLM では **逆効果になるケースが多い**です。

具体的には、Thinking を ON にすると以下の問題が発生しやすくなりました。

- **長大な思考ループ** に入り、ClawX への応答を返さずに終了してしまう
- 処理時間が大幅に増加し、タイムアウトが発生する
- コンテキストを思考トークンで消費し、実際の作業に使えるトークンが減る

ローカルの 9B モデルはクラウドの大規模モデルと比べてリソースが限られているため、Thinking を ON にして得られるメリットよりデメリットのほうが大きくなります。**まずは OFF で試してみることを推奨**します。

---

## 4. Temperature

**設定場所**: LM Studio → モデル設定 → Temperature

Temperature はモデルの回答の「ランダム性」を制御するパラメータです。値が高いほど多様で創造的な回答が生まれ、低いほど一貫性のある決定論的な回答になります。

### 推奨値: `0.77`

筆者はデフォルト値（多くの場合 1.0）から少し下げた `0.77` を使用しています。この値にした理由は以下の通りです。

- コーディングや設定変更といった **精度が求められるタスク** では、ある程度低い Temperature のほうが安定した結果を得やすい
- ただし、0 に近づけすぎると回答が硬直化して柔軟性が失われる
- 0.77 は **創造性と安定性のバランスが良い** と感じた値

デフォルト値のままでも ClawX との連携自体は動作しますが、予期しない回答のばらつきが気になる場合はここを調整してみてください。

## 指示の出し方について

設定以外にも、**どのように指示を出すか**がローカル LLM の成功率に大きく影響します。

### シンプルなタスクに分割する

複雑な指示を一度に出すと、以下の問題が起きやすくなります。

- コンテキストが指示や思考で埋まり、作業結果を返す余裕がなくなる
- LLM が何をすべきか迷い、ClawX への応答を忘れて終了する
- 処理時間が長くなり、タイムアウトする

「ファイルを作成して、内容を書いて、別のファイルに移動して、元のファイルを削除して」といった複合的な指示は、ステップごとに分けて出すほうが成功率が上がります。

### 良い指示の例

```
# あまり良くない指示
プロジェクトのREADMEを更新して、CIの設定も直して、不要なファイルも削除してください。

# より良い指示
まずREADMEの概要セクションだけ更新してください。
（完了後）次にCIの設定ファイルを確認して修正点を教えてください。
```
